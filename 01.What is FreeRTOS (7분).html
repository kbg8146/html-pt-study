01

RTOS는?

정의

작업이 정해진 시간 안에 끝나도록 보장하는 운영체제

핵심

'빠른 OS'가 아니라 '늦지 않는 OS'

특징
  • 우선순위 선점 스케줄링: 급한 작업이 생기면 즉시 CPU를 넘겨줌
  • 멀티태스킹: 여러 작업을 태스크로 나눠 동시에 도는 것처럼 실행
  • 작은 크기: 수 KB ~ 수십 KB, MCU에서도 동작
HARD REAL TIME놓치면 실패 (에어백, 유도 제어)
SOFT REAL TIME놓치면 품질 저하 (영상 스트리밍)
02

RTOS vs 일반 OS

항목RTOS일반 OS (리눅스 등)
목표최악 응답 시간 보장평균 처리량, 공정한 분배
실행 단위태스크 (메모리 전부 공유 = 스레드와 같은 구조)프로세스 (MMU로 메모리 격리) + 스레드
하드웨어MMU 없어도 됨 (Cortex-M 등 MCU)보통 MMU 필요 (Cortex-A, x86)
부팅ms 단위초 단위
RTOS주기와 응답 시간이 중요한 제어 (모터, 센서, 비행 제어)
일반 OS화면, 네트워크, 파일 처리가 많은 응용
같이 쓰기Zynq처럼 코어 0은 리눅스, 코어 1은 FreeRTOS (AMP)

05

태스크 만들기: xTaskCreate

xTaskCreate(vSensorTask,   // 실행할 함수
            "Sensor",      // 이름 (디버깅용)
            256,           // 스택 크기: 워드 단위 (256워드 = 1 KB)
            NULL,          // 넘길 인자
            3,             // 우선순위 (0이 가장 낮음)
            NULL);         // 핸들 (필요 없으면 NULL)
void vSensorTask(void *pvParameters) {
    for (;;) {             // 무한 루프, return 금지
        // 할 일
    }
}
  • 반환값이 pdPASS가 아니면 실패 (힙 부족)
06

태스크 상태

Running실행 중
Ready차례 대기
Blocked기다리는 중, CPU 안 씀
Suspended강제 정지
Ready → Running스케줄러가 가장 높은 우선순위를 고름
Running → BlockedvTaskDelay, 큐·세마포어 대기
Blocked → Ready시간이 되거나 데이터·신호가 오면 스스로 풀림
07

주기 맞추기: vTaskDelay vs vTaskDelayUntil

TickType_t xLastWake = xTaskGetTickCount();          // 기준 시각
for (;;) {
    read_sensor();                                    // 작업: 3 ms 걸림
    vTaskDelayUntil(&xLastWake, pdMS_TO_TICKS(10));   // 10 ms 주기
}
vTaskDelay(10)끝난 뒤부터 10 ms → 주기 13 ms
0132639
vTaskDelayUntil(10)지난번 깬 시각부터 10 ms → 주기 10 ms
0102030
작업 (3 ms)쉬는 시간숫자 = 깨어나는 시각 (ms)
주기가 정확해야 하는 작업에는 vTaskDelayUntil
08

메모리: 힙과 스택

FreeRTOS 힙태스크 스택 · 큐 · 세마포어가 여기서 할당. configTOTAL_HEAP_SIZE 크기의 전역 배열
힙 방식heap_1 ~ heap_5 중 보통 heap_4 (해제 + 빈 블록 병합)
정적 할당xTaskCreateStatic: 실행 중 할당 실패가 없음 → 안전이 중요한 시스템
스택 확인uxTaskGetStackHighWaterMark: 가장 적게 남았던 여유 공간
09

스케줄러: vTaskStartScheduler

int main(void) {
    HAL_Init();                                               // 하드웨어 초기화
    xTaskCreate(vSensorTask, "Sensor", 256, NULL, 3, NULL);   // 태스크부터 만들고
    vTaskStartScheduler();                                    // 스케줄러 시작 (정상이면 안 돌아옴)
    for (;;);                                                 // 힙 부족일 때만 도달
}
선점형높은 우선순위가 준비되면 즉시 CPU를 가져감
라운드로빈같은 우선순위끼리는 Tick(보통 1 ms)마다 번갈아
우선순위 원칙주기가 짧은 태스크를 높게 (Rate Monotonic)
10

큐: 태스크끼리 데이터 주고받기

태스크는 메모리를 공유 → 전역 변수로 넘기면 레이스 컨디션. 그래서 큐로 값을 복사해서 전달

xSensorQueue = xQueueCreate(8, sizeof(int16_t));          // 8개짜리 큐 (스케줄러 시작 전에)

// 센서 태스크: 보내기
xQueueSend(xSensorQueue, &value, 0);                     // 꽉 차면 바로 포기

// 제어 태스크: 받기
xQueueReceive(xSensorQueue, &rx, portMAX_DELAY);         // 올 때까지 대기
  • 마지막 인자 = 기다릴 시간. 0이면 바로 포기, portMAX_DELAY면 올 때까지 (그동안 Blocked)
11

세마포어와 뮤텍스

세마포어 → 신호용소유권 없음, 다른 쪽이 Give해서 신호 전달
뮤텍스 → 자원 보호용잡은 태스크가 직접 풀어야 함, 우선순위 역전 완화
xUartMutex = xSemaphoreCreateMutex();                           // 만들기

if (xSemaphoreTake(xUartMutex, pdMS_TO_TICKS(100)) == pdTRUE) {  // 얻기 (100 ms까지 대기)
    printf("temp = %d\r\n", value);                              // UART 혼자 사용
    xSemaphoreGive(xUartMutex);                                   // 꼭 돌려주기
}
  • 우선순위 역전: 높은 태스크가 낮은 태스크의 뮤텍스를 기다리는 사이 중간 태스크가 끼어들어 높은 태스크가 늦어짐 → 뮤텍스는 우선순위 상속으로 완화
12

정리: 전체 코드 한 편

QueueHandle_t xSensorQueue;

void vSensorTask(void *pvParameters) {
    TickType_t xLastWake = xTaskGetTickCount();
    for (;;) {
        int16_t value = read_sensor();
        xQueueSend(xSensorQueue, &value, 0);              // 10 큐로 보내기
        vTaskDelayUntil(&xLastWake, pdMS_TO_TICKS(10));   // 07 10 ms 주기
    }
}

void vControlTask(void *pvParameters) {
    int16_t value;
    for (;;) {
        if (xQueueReceive(xSensorQueue, &value, portMAX_DELAY) == pdPASS) {  // 10 받기
            control(value);
        }
    }
}

int main(void) {
    xSensorQueue = xQueueCreate(8, sizeof(int16_t));            // 10 큐 만들기
    xTaskCreate(vSensorTask,  "Sensor",  256, NULL, 3, NULL);   // 05 주기 짧아 높게
    xTaskCreate(vControlTask, "Control", 256, NULL, 2, NULL);
    vTaskStartScheduler();                                      // 09 스케줄러 시작
    for (;;);
}
FreeRTOS = 태스크를 만들고(xTaskCreate) → 스케줄러를 돌리고(vTaskStartScheduler) → 큐·세마포어로 협업
