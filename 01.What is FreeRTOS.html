01

RTOS는?

정의

작업이 정해진 시간 안에 끝나도록 보장하는 운영체제

의미
  • "정해진 시간" = 실시간성(Real-time capability). 작업마다 늦으면 안 되는 데드라인이 있음
  • "보장" = 결정성(Determinism). 평균이 아니라 최악의 경우에도 응답 시간을 미리 계산할 수 있음
  • RTOS는 '빠른 OS'가 아니라 '늦지 않는 OS'. 평균이 빨라도 가끔 늦으면 실시간 시스템이 아님
특징
  • 우선순위 기반 선점 스케줄링: 급한 작업이 생기면 즉시 CPU를 넘겨줌
  • 멀티태스킹: 여러 작업을 태스크로 나눠 동시에 도는 것처럼 실행
  • 작은 크기: 수 KB ~ 수십 KB, MCU에서도 동작
HARD REAL TIME놓치면 실패 (유도 제어, 에어백)
SOFT REAL TIME놓치면 품질 저하 (영상 스트리밍)

태스크 함수와 상태

  • 태스크 함수 작성 규칙: 무한 루프로 작성, return 금지. 끝내려면 vTaskDelete(NULL)
void vSensorTask(void *pvParameters) {
    for (;;) {
        // 할 일
    }
}
Running실행 중
Ready실행 가능, 차례 대기
Blocked기다리는 중, CPU 안 씀
Suspended명시적으로 정지
Ready → Running스케줄러가 가장 높은 우선순위를 고름
Running → BlockedvTaskDelay, 큐·세마포어 대기
Blocked → Ready시간이 되거나 데이터·신호가 옴 (스스로 풀림)
SuspendedvTaskSuspend로 들어가고 vTaskResume으로만 나옴 (누가 깨워야 풀림)

주기 맞추기: vTaskDelay, vTaskDelayUntil

void vTaskDelay(TickType_t xTicksToDelay);            // 지금부터 쉴 Tick 수

void vTaskDelayUntil(TickType_t *pxPreviousWakeTime,  // 기준 시각 변수의 주소 (자동 갱신)
                     TickType_t xTimeIncrement);      // 주기 (Tick)
void vSensorTask(void *pvParameters) {
    TickType_t xLastWake = xTaskGetTickCount();          // 기준 시각 초기화
    for (;;) {
        read_sensor();
        vTaskDelayUntil(&xLastWake, pdMS_TO_TICKS(10));  // 10 ms 주기 (ms → Tick 변환)
    }
}
  • vTaskDelay: 호출한 시점부터 셈 → 작업에 3 ms 걸리면 주기가 13 ms로 밀림
  • vTaskDelayUntil: 기준 시각부터 셈 → 작업 시간과 상관없이 주기 일정
08

메모리: 힙과 스택

  • xTaskCreate로 만든 태스크의 스택과 태스크 정보(TCB)는 FreeRTOS가 관리하는 메모리 풀에서 할당. 큐·세마포어도 여기서 할당
  • 이 메모리 풀은 ucHeap[configTOTAL_HEAP_SIZE]라는 큰 전역 배열 (메모리 맵상 .bss 영역)
  • C 언어의 malloc 힙과는 별개. 단, heap_3은 표준 malloc을, heap_5는 직접 지정한 영역을 사용
방식특징
heap_1할당만, 해제 없음 (가장 단순)
heap_2해제 가능, 빈 블록 병합 없음
heap_3표준 malloc/free를 감싼 것
heap_4해제 + 인접 빈 블록 병합 (가장 많이 씀)
heap_5heap_4 + 떨어진 여러 메모리 영역 사용
정적 할당xTaskCreateStatic: 스택과 TCB 버퍼를 직접 넘김. 메모리가 컴파일 때 확정되어 실행 중 할당 실패가 없음 → 안전이 중요한 시스템에서 선호
스택 사용량uxTaskGetStackHighWaterMark(핸들): 지금까지 남았던 최소 여유 공간 (워드 단위)
오버플로 감지configCHECK_FOR_STACK_OVERFLOW + vApplicationStackOverflowHook
남은 힙xPortGetFreeHeapSize(): 지금 남은 양, xPortGetMinimumEverFreeHeapSize(): 지금까지 가장 적게 남았던 양 (힙 크기 정할 때 기준)

스케줄러: vTaskStartScheduler

void vTaskStartScheduler(void);   // 매개변수 없음, 정상이면 돌아오지 않음
int main(void) {
    HAL_Init();                                               // 하드웨어 초기화
    xTaskCreate(vSensorTask, "Sensor", 256, NULL, 3, NULL);   // 태스크부터 만들고
    vTaskStartScheduler();                                    // 스케줄러 시작
    for (;;);                                                 // 힙 부족일 때만 여기 도달
}
  • 태스크를 다 만든 뒤 호출하면 스케줄러가 시작되고, 정상이면 돌아오지 않음 (힙이 부족할 때만 돌아옴)
  • 호출할 때 Idle 태스크(우선순위 0)가 자동으로 만들어짐: 할 일이 없을 때 실행, 삭제된 태스크 메모리 정리. 타이머를 쓰면 타이머 태스크도 생성
선점형높은 우선순위가 준비되면 즉시 CPU를 가져감
라운드로빈같은 우선순위끼리는 Tick마다 번갈아
Tick타이머 인터럽트로 스케줄러가 깨어나는 주기 (Cortex-M은 SysTick)
// FreeRTOSConfig.h
#define configUSE_PREEMPTION     1     // 선점형 사용
#define configUSE_TIME_SLICING   1     // 같은 우선순위 라운드로빈
#define configTICK_RATE_HZ       1000  // Tick 1 ms
#define configMAX_PRIORITIES     5     // 우선순위 개수
  • 컨텍스트 스위칭: 레지스터를 태스크 스택에 저장하고 SP는 TCB에 기록, 다음 태스크의 SP로 바꿔 복원 (Cortex-M은 PendSV 인터럽트에서 처리)
  • 우선순위 원칙: 주기가 짧은 태스크를 높게 (Rate Monotonic)

큐 만들기: xQueueCreate

QueueHandle_t xQueueCreate(UBaseType_t uxQueueLength,  // 몇 개까지 쌓을지
                           UBaseType_t uxItemSize);    // 항목 하나 크기 (바이트)
QueueHandle_t xSensorQueue;                              // 핸들은 전역에 선언

int main(void) {
    xSensorQueue = xQueueCreate(8, sizeof(int16_t));     // int16_t 8개짜리 큐
    if (xSensorQueue == NULL) {
        // 실패: 힙 부족
    }
    // 그다음 태스크 생성, vTaskStartScheduler()
}
  • 생성 시점: 스케줄러 시작 전에, 큐를 쓰는 태스크보다 먼저 (안 그러면 NULL 핸들로 접근)
  • 용도: 태스크 간 데이터 전달. 태스크끼리 메모리를 공유하기 때문에 전역변수로 넘기면 레이스 컨디션이 생길 수 있음
  • 값을 복사해서 넣음 → 보낸 쪽 변수가 바뀌어도 안전. 큰 데이터는 포인터를 넣음

큐 보내기와 받기: xQueueSend, xQueueReceive

BaseType_t xQueueSend(QueueHandle_t xQueue,          // 큐 핸들
                      const void *pvItemToQueue,     // 보낼 데이터의 주소
                      TickType_t xTicksToWait);      // 꽉 찼을 때 기다릴 시간

BaseType_t xQueueReceive(QueueHandle_t xQueue,       // 큐 핸들
                         void *pvBuffer,             // 받은 데이터를 저장할 주소
                         TickType_t xTicksToWait);   // 비었을 때 기다릴 시간
// 보내는 쪽 (센서 태스크 루프 안)
int16_t value = read_sensor();
xQueueSend(xSensorQueue, &value, 0);                     // 꽉 차면 바로 포기

// 받는 쪽 (제어 태스크 루프 안)
int16_t rx;
if (xQueueReceive(xSensorQueue, &rx, portMAX_DELAY) == pdPASS) {  // 올 때까지 대기
    control(rx);
}
  • 기다리는 시간: 0이면 바로 포기, portMAX_DELAY면 올 때까지 대기 (그동안 Blocked, CPU 안 씀)
  • 반환값: 성공하면 pdPASS, 기다린 시간 안에 못 하면 실패

세마포어와 뮤텍스

세마포어소유권 없음, ISR에서도 Give 가능 → 신호용
뮤텍스잡은 태스크가 직접 풀어야 함, 우선순위 상속으로 역전 완화, ISR에서 사용 불가 → 자원 보호용
  • 종류: 바이너리(신호용, 처음엔 비어 있어서 Give가 먼저 와야 Take 가능), 카운팅(개수 세기), 뮤텍스(공유 자원 보호)
  • 우선순위 역전: 높은 태스크가 낮은 태스크가 쥔 뮤텍스를 기다림 → 그사이 중간 태스크가 낮은 태스크를 선점 → 결국 높은 태스크가 중간 태스크보다 늦게 실행됨. 사례: 1997년 화성 패스파인더, 우선순위 상속을 켜서 해결
  • 데드락: 서로 상대가 쥔 뮤텍스를 기다림 → 잡는 순서를 통일

세마포어 함수: Create, Take, Give

SemaphoreHandle_t xSemaphoreCreateBinary(void);   // 처음엔 비어 있음 (Give 먼저)
SemaphoreHandle_t xSemaphoreCreateMutex(void);    // 처음부터 Take 가능

인터럽트와 FreeRTOS

BaseType_t xSemaphoreGiveFromISR(SemaphoreHandle_t xSemaphore,            // 줄 세마포어 핸들
                                 BaseType_t *pxHigherPriorityTaskWoken);  // 더 높은 태스크를 깨우면 pdTRUE가 됨

portYIELD_FROM_ISR(xHigherPriorityTaskWoken);                             // pdTRUE면 ISR 끝나자마자 전환
void UART_IRQHandler(void) {
    BaseType_t xWoken = pdFALSE;                // 처음엔 pdFALSE
    xSemaphoreGiveFromISR(xRxSem, &xWoken);  // 처리 태스크 깨우기
    portYIELD_FROM_ISR(xWoken);              // 바로 전환
}

void vUartTask(void *pvParameters) {
    for (;;) {
        xSemaphoreTake(xRxSem, portMAX_DELAY);  // ISR 신호 올 때까지 Blocked
        // 받은 데이터 처리
    }
}
  • ISR 안에서는 FromISR 버전만 사용. 기다릴 수 없어서 대기 시간 매개변수가 없음 (xQueueSendFromISR, vTaskNotifyGiveFromISR도 같은 방식)
  • 원칙: ISR은 알리기, 처리는 태스크 (Deferred Processing)
  • 주의: configMAX_SYSCALL_INTERRUPT_PRIORITY보다 높은 우선순위 ISR에서는 FreeRTOS API 호출 금지. STM32 기본값 5: API를 부르는 ISR은 NVIC 우선순위를 5 이상으로 (숫자가 클수록 낮음)

그 외 기능

태스크 알림xTaskNotifyGive / ulTaskNotifyTake: 받는 태스크가 하나로 정해진 신호를 세마포어보다 가볍고 빠르게 (별도 객체 없음). 앞 장의 ISR → 태스크 신호가 대표적인 사용처
이벤트 그룹xEventGroupSetBits / xEventGroupWaitBits: 여러 조건이 모두(또는 하나라도) 갖춰질 때까지 대기
소프트웨어 타이머xTimerCreate / xTimerStart: 일정 시간 뒤나 주기적으로 콜백 실행. 콜백은 타이머 태스크에서 돌기 때문에 블로킹 금지

정리: 전체 코드 한 편

QueueHandle_t xSensorQueue;

void vSensorTask(void *pvParameters) {
    TickType_t xLastWake = xTaskGetTickCount();           // 07 기준 시각 초기화
    for (;;) {
        int16_t value = read_sensor();
        xQueueSend(xSensorQueue, &value, 0);              // 11 보내기 (꽉 차면 포기)
        vTaskDelayUntil(&xLastWake, pdMS_TO_TICKS(10));   // 07 10 ms 주기
    }
}

void vControlTask(void *pvParameters) {
    int16_t value;
    for (;;) {
        if (xQueueReceive(xSensorQueue, &value, portMAX_DELAY) == pdPASS) {  // 11 받기 (올 때까지 대기)
            control(value);
        }
    }
}

int main(void) {
    xSensorQueue = xQueueCreate(8, sizeof(int16_t));            // 10 큐 만들기
    xTaskCreate(vSensorTask,  "Sensor",  256, NULL, 3, NULL);   // 05 태스크 만들기 (주기 짧아 높게)
    xTaskCreate(vControlTask, "Control", 256, NULL, 2, NULL);
    vTaskStartScheduler();                                      // 09 스케줄러 시작
    for (;;);                                                   // 힙 부족일 때만 여기 도달
}
RTOS는 최악 응답 시간 보장. FreeRTOS는 태스크를 만들고(xTaskCreate) → 스케줄러를 돌리고(vTaskStartScheduler) → 큐·세마포어로 협업하는 구조
